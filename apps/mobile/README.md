# DSH Mobile iroh Android App

[Project overview](../../README.md) · [Verification](../../VERIFICATION.md) · [Integration design](../../docs/INTEGRATION_SEAM.md)

The independent app reuses DSH Mobile's device list, pairing screens, startup preference, WebView, cancellation, Back, page scaling, file selection, camera, notifications and localization. Its application ID is `io.github.sayach.dshmobileiroh`: it does not replace the production app or migrate that app's data.

## Implemented transport

Native-enabled builds add an experimental iroh pairing entry. Scan or paste a short-lived descriptor generated by the trusted host operator, connect, name the computer, then open DSH. Saved devices reconnect through iroh before renewing their normal Mobile Gateway credentials. The independent [computer console](../../operator/README.md) composes the native Host/Gateway owners, provisions private certificates and generates short-lived pairing QR codes; no normal DSH profile is automatically discovered or changed.

The Rust client owns QUIC and a fixed loopback TCP listener. WebView uses the full peer-derived HTTPS hostname; Java authentication and downloads use a separate restricted CONNECT proxy to that exact hostname. TLS still terminates at the computer's Mobile Gateway. Neither transport bridge decrypts page traffic or receives a DSH launch cookie.

Cancel, device switching, removal and Activity destruction invalidate the current request. Late connection results cannot reopen an old page or close a newer device. An authenticated online transport revocation closes the current connection; ordinary network errors are not labelled as revocation. Offline transport-only revocation still needs a new pairing/recovery flow and is not guaranteed to produce the specific “removed” label. Mobile Gateway `device_revoked` remains a separate authorization result.

Gateway tokens and CA credentials use the existing Android Keystore encryption. The long-term iroh endpoint key is currently an app-private native file, not hardware-backed Keystore-wrapped storage. Short pairing codes and complete descriptors are not saved as credentials.

Retained-page recovery restarts foreground transport monitoring for the replacement carrier. Retries share the original connection deadline; old queued checks cannot apply to its successor. QR validation uses Android-compatible, non-backtracking repetitions for bounded JSON tokens, retaining strict field/escape checks and the 2200-byte descriptor limit. JVM tests and the limited physical Activity/WebView observations are listed separately in [VERIFICATION](../../VERIFICATION.md).

## Build

Use JDK 17, Android SDK 36, installed Build Tools with 16 KB ZIP-alignment support and an explicit NDK. NDK `25.2.9519653` and Build Tools `35.0.0` are locally verified; CI provisions Build Tools `36.0.0`. Select the installed Build Tools directory explicitly for inspection. Configure the SDK locally; do not commit `local.properties`.

```powershell
Set-Location apps/mobile/android
./gradlew.bat --no-daemon -PirohNative=true -PirohNdk=C:/develop/Android/Sdk/ndk/25.2.9519653 lintDebug testDebugUnitTest assembleDebug assembleRelease -x lintAnalyzeDebugUnitTest -x lintAnalyzeDebugAndroidTest
```

The Gradle task builds both native libraries. Omitting `-PirohNative=true` builds the original HTTPS shell without an iroh entry, not a usable iroh transport. It cannot be used to validate this feature.

This is the executed CI-equivalent command: Android Lint covers application source, Manifest and resources. Test-source Android Lint is excluded; JVM tests still compile and run separately. There are no instrumentation test sources at present. Do not describe this as an all-source lint result.

| Artifact | Output | Meaning |
| --- | --- | --- |
| Debug APK | `android/app/build/outputs/apk/debug/app-debug.apk` | Local independent test app; debug signer |
| Release APK | `android/app/build/outputs/apk/release/app-release-unsigned.apk` | R8/shrinking check; unsigned, not a distributable release |
| Native libraries in Gradle | `android/app/build/generated/iroh/jniLibs/` | Generated for APK packaging; never committed |
| Standalone native output | Repository `artifacts/android/jniLibs/` | Default only when invoking the script without `--output` |

Native-enabled APKs currently support **arm64-v8a and x86_64 only**, with minimum Android 10/API 29. They do not yet cover 32-bit Android devices. A future main-App integration must deliberately preserve its supported devices and signing policy; do not substitute this APK for every production user.

From the repository root, verify native exports, architecture and ELF/ZIP alignment:

```powershell
node scripts/build-android-transport.mjs --ndk C:/develop/Android/Sdk/ndk/25.2.9519653 --verify-apk apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk --build-tools C:/develop/Android/Sdk/build-tools/35.0.0
```

The checker requires all four JNI methods (`initialize`, `connect`, `close`, `status`) in both libraries, 16 KB ELF LOAD/RELRO alignment and APK ZIP alignment. Static checks and a successful R8 build do not prove JNI initialization on an Android device.

## Device acceptance

No data clear, production-app uninstall or signer bypass is part of testing. Identify the device, app package, signer and WebView version before installing. Use an explicitly owned isolated pairing; remove only that pairing afterwards.

Required device coverage includes fresh QR pairing, cold-start reconnect, cancel at each connection stage, switching while a connection is pending, Back, file selection/download, visible-page state during reconnection, online revocation, offline revocation recovery, app restart, screen sleep and network changes. Test both a direct path and a real relay/mobile-network topology. Record unavailable checks rather than treating JVM tests or the host transport driver as physical-device evidence.

The independent app version is `0.1.0-alpha.1`. Its Mobile Gateway compatibility marker remains `0.6.5`, the imported app/API baseline; this marker is not a second product version or a statement that this experiment is a released DSH Mobile app.
